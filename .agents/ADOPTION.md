# 渐进式迁移与落地实施指南 (ADOPTION v1)

> 核心方针：**整理现有指令，做最小可用接线，绝不推倒重建，绝不另起重型编排平台**。

---

## 1. 四阶段迁移路线 (A-B-C-D)

```
┌──────────────────┐     ┌──────────────────┐     ┌──────────────────┐     ┌──────────────────┐
│ A. 盘点有效入口  │ ──> │ B. 最小可用接线  │ ──> │ C. 真实任务验证  │ ──> │ D. 渐进替换收口  │
│ 梳理既有规则来源 │     │ 接入三核心角色   │     │ 闭环一个真实任务 │     │ 纳入其余生态工程 │
└──────────────────┘     └──────────────────┘     └──────────────────┘     └──────────────────┘
```

### 阶段 A：盘点有效入口 (Inventory)
1. 清点项目现存的指示性文件（如 `AGENTS.md`、`README.md`、`ARCHITECTURE.md`、`.cursor/`）。
2. 明确有效约束的来源与优先级，切断过期的历史死链接。
3. 将散落的“经验提示词”提炼入 `.agents/rules/shared-rules.md`，保留业务专属契约于 `PROJECT.md`。

### 阶段 B：最小可用接线 (Minimal Wiring)
1. 默认仅激活核心三角色：**主控 (Orchestrator)、实现 (Implementer)、独立审计 (Auditor)**。
2. 5 类按需专家（架构/产品/研究/安全/发布）保持静默，仅在出现特定瓶颈时定向按需唤醒。
3. 配置工具层薄引用（如 Claude `@AGENTS.md`，Antigravity Subagent ACL），不制造重复副本。

### 阶段 C：真实任务验证 (Single Real Handoff)
1. **绝不为了做演练而伪造无意义任务**。直接从用户已批准的真实需求中挑选一个微小改进（例如修复一个边界条件或优化一段测试）。
2. 走通一次完整的协作闭环：
   - 主控出具标准 `TASK.md` 工单（带明确基线与 AC）。
   - 实现者修改代码，产出候选 Commit 与局部测试证据。
   - 独立审计角色基于 Commit SHA 核验，出具 `[PASS]` 结论并关闭任务。
3. 检查是否有越权写入、跨界修改或多余的无限全仓审计。

### 阶段 D：渐进替换与版本固化 (Gradual Rollout)
1. 所有规则与提示词随 Git 仓库一同版本化演进。
2. 每次微调提示词都记录对应的解决痛点与实际效果对比。
3. 逐步将规范推广至 PromptPlaza、shortdrama 等其他活跃工程。

## 2. 防无限审计机制（Anti-Infinite-Audit Protocol）

为彻底根治“AI 助手在每次交付时都会顺手提出大量重构要求，导致任务永远无法关闭”的顽疾，强制执行以下阻断防线：

1. **一票关闭原则**：只要工单中预设的验收条件（AC）全部获得客观证据支持，且没有造成任何新的编译/回归测试失败，**主控角色与审计角色必须立刻关闭当前工单**。
2. **建议隔离区 (`[SUGGESTION]`)**：
   - 任何非阻断性代码异味、长远可优化点、审美分歧，一律存入交接单的 `[SUGGESTION]` 列表。
   - 建议项**绝无资格**扣押当前任务的交付。
3. **有限授权队列**：用户的“继续”或“推进”仅用于驱动原定授权队列中的下一项，绝不允许 AI 自行脑补出一长串未批准的“建议改造列表”反客为主。
